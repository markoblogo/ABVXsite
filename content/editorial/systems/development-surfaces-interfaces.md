# Development Surfaces & Interfaces for AI-Native Tools

AI-native development tools need surfaces where people can find out what exists and understand how to use it. A catalogue, interface or theme system can turn a collection of repositories and workflows into something that is easier to navigate, inspect and maintain.

[ABVX Lab](/work/abvx-lab) is the public catalog and control surface for the ABVX AI coding stack. It brings repository context, orchestration, skills, discovery and proof surfaces into one place. [AsciiTheme](/work/ascii-theme) is a UI and CSS system for light, dark and ASCII-inspired development interfaces. These projects operate at different levels: one organizes access to tools, while the other explores how development interfaces can be presented.

## Interfaces are part of the workflow

A well-designed developer surface should expose useful choices without obscuring their limits. People need to see what a tool does, where its source or documentation lives, and what evidence supports a status or capability. Clear navigation helps a user move from discovery to inspection and then to a relevant repository or project page.

Theme and component systems serve a related but narrower need. They provide repeatable visual patterns for interfaces so that individual tools do not have to invent every display decision from scratch. Their value depends on usability, accessibility and fit with the environment where they are applied.

## Keep the public surface legible

Documentation and interfaces work together. A catalog can make relationships visible; a design system can make controls recognizable; project pages can point to source repositories and external surfaces. No one page needs to replace the underlying tool.

Explore [ABVX Lab](/work/abvx-lab) and [AsciiTheme](/work/ascii-theme) for examples of how developer-facing surfaces and interface systems contribute to AI-native work.
