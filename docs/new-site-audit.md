# ABVX New Site Audit

Date: 2026-05-09  
Scope: preparation for a full redesign of `abvx.xyz` without changing production behavior.

## Goal

The next version of the site should become a live working index of Anton Biletskiy-Volokh's current work:

- complex systems
- strategy and product development
- market infrastructure
- AI-native and agentic development
- web services and protocols
- constructed-language and language-AI experiments
- books, translations, and publishing projects
- essays from Medium and Substack

The current codebase already started moving away from the old six-ecosystem model, but legacy concepts are still present in routing, data fetching, sitemap, metadata, `llms.txt`, and several pages.

## Target Public IA

The redesign should use this public structure:

- `/focus`: Current Focus, mainly agro-commodity trading infrastructure.
- `/systems`: Systems Catalogue, including web services, AI/dev tools, protocols, language experiments, and technical companions.
- `/books`: ABVX Press: books, translations, series, and publishing projects.
- `/writing`: Medium + Substack RSS archive.
- `/about`: short professional framing, links, and contact.

Important IA rule: "ecosystems" should not be the main public information architecture.

## What Should Be Replaced

Replace in the redesign:

- Public navigation based on `DIRECTIONS` with target IA: `/focus`, `/systems`, `/books`, `/writing`, `/about`.
- "Ecosystems" language in home page, metadata, `llms.txt`, sitemap priorities, and support pages.
- `/books` implementation grouped by legacy `Ecosystem` relation; new `/books` should be ABVX Press grouped by series, format, language, and publishing status.
- `/projects` as a primary public route; systems work should move into `/systems`.
- `/cropto` as the primary Cropto page; target should be `/focus`.
- `/abvx-press` as separate public page; target says `/books` should carry ABVX Press.
- `/tech-lab` and `/lang-lab` as separate primary nav pages; target says both should roll into `/systems` with filters/groups.
- Static `/llmo` and `/toki-pona` pillar pages in their current form; their content should become systems catalogue clusters or redirects.
- Manual RSS XML parsing if feed reliability becomes important; a small parser dependency could be justified later, but not before the redesign scope is locked.

## Migration Risks

Primary risks:

- SEO loss from changing public URLs without redirects.
- Existing indexed `/ecosystems/*`, `/projects`, `/cropto`, `/abvx-press`, `/tech-lab`, `/lang-lab`, `/llmo`, and `/toki-pona` URLs need deliberate redirect or compatibility decisions.
- Notion schema is mixed: legacy relation model and new direction fields coexist. Removing the legacy model too early can break `/books`, `/projects`, `/ecosystems`, and sitemap generation.
- Some new Notion cards are draft or incomplete; a redesign that blindly lists all items may expose unfinished cards.
- `Related Directions` multi-select and `Related Directions Text` duplicate meaning. The app currently prefers the text field because connector updates for multi-select were limited.
- RSS fetches are external network dependencies and can fail or change XML shape.
- `NOTION_TOKEN` is required for dynamic Notion pages; build/runtime behavior depends on deployment env.
- `public/llms.txt` is stale and may mislead LLM crawlers after IA changes if not updated at the same time.
- The current lint baseline is not clean; redesign work should either fix baseline first or avoid mixing lint cleanup with IA changes.

Specific code risks:

- `src/app/sitemap.ts` still fetches legacy ecosystems and emits `/ecosystems/[slug]`.
- `src/app/books/page.tsx` has unused `ecoById` and legacy ecosystem grouping.
- `src/app/toki-pona/page.tsx` links to `/ecosystems`, `/projects`, and `/books`.
- `src/app/work-with-me/page.tsx`, `/llmo`, and `/links` still link to legacy routes.
- `src/lib/abvx-data.ts` has type declarations placed after function declarations. It typechecks, but should be cleaned during refactor for readability.

```text

  focus/
    page.tsx                       # current focus: agro-commodity trading infrastructure
  systems/

  writing/

  about/
    page.tsx                       # professional framing + links/contact
  robots.ts
  sitemap.ts

src/components/
  layout/
    site-header.tsx
    site-footer.tsx
  cards/
    system-card.tsx

  sections/

    systems-catalogue.tsx
    press-series.tsx
  writing-list.tsx
  zoomable-image.tsx

src/lib/
  cms/

    notion-mappers.ts              # property parsing and normalization
```

Migration principle:

- Create new model and pages beside the current implementation first.
- Keep legacy routes live until new pages are verified.
- Add redirects only after new pages have equivalent content and metadata.
- Remove legacy Notion ecosystem code only after all public pages, sitemap, and redirects no longer depend on it.

## Recommended Redesign Sequence

1. Freeze the public route contract:
   - `/focus`
   - `/systems`
   - `/books`
   - `/writing`
   - `/about`

2. Create `src/lib/routes.ts`:
   - canonical route constants
   - legacy route table
   - shared nav config

3. Create a normalized content model:
   - `FocusItem`
   - `SystemItem`
   - `BookItem`
   - `WritingItem`

4. Refactor Notion mapping without deleting legacy fetchers:
   - keep existing `getProjects`, `getBooks`, `getEcosystems`
   - add new selectors/mappers that derive target IA from current Notion fields
   - filter out incomplete draft items unless explicitly allowed

5. Build new pages in parallel:
   - Add `/focus`.
   - Add `/systems`.
   - Rebuild `/books` in ABVX Press framing.
   - Refresh `/writing` labels and failure states.
   - Rewrite `/about` with short professional framing and all key links.

6. Update metadata and machine-facing files:
   - `src/app/layout.tsx`
   - `src/app/sitemap.ts`
   - `src/app/robots.ts`
   - `public/llms.txt`

7. Verify without redirects:
   - `npm run lint`
   - `npm run build`
   - manual route check for all new pages
   - inspect sitemap output

8. Add redirects in a separate commit:
   - update `next.config.ts`
   - keep legacy pages in code for one release if needed
   - verify redirect status and canonical URLs

9. Remove or archive legacy code only after redirects are live and verified:
   - `/ecosystems`
   - `/projects`
   - obsolete direction pages
   - legacy ecosystem cards/helpers if unused

## Immediate Next Step

The next implementation task should be small and reversible:

- Add `/focus` and `/systems` pages while keeping every current route unchanged.
- Do not redirect anything yet.
- Use the existing Notion direction fields to populate them.
- Keep `/books`, `/writing`, and `/about` behavior unchanged in that first implementation pass.

This creates the new IA beside production behavior and gives a safe visual review point before route migration.
